# AgentShield Source Provenance & Data Lineage Specification

This document details the architecture, data models, content hashing, multi-parent lineage graphs, integrity verification, and audit integration for **Phase 6: Source Provenance & Data Lineage** in AgentShield.

---

## 1. Purpose & Core Distinctions

AgentShield strictly separates content trust classification from source provenance tracking:

- **Trust Classification (Phase 4)** answers: *"What trust level does this content have?"* (`TRUSTED`, `INTERNAL`, `USER_CONTROLLED`, `UNTRUSTED`, `UNKNOWN`)
- **Source Provenance (Phase 6)** answers: *"Where did this content originate, how was it derived, and can we verify its SHA-256 integrity?"*

---

## 2. Provenance Record Schema

Every source payload registered with AgentShield produces a `ProvenanceRecord` containing explicit origin and SHA-256 hash metadata:

| Field Name | Type | Description |
|---|---|---|
| `provenance_id` | `str` (UUID) | Unique authoritative identifier for this provenance record. |
| `source_category` | `SourceCategory` | Category of origin (`SYSTEM`, `USER`, `INTERNAL_DATABASE`, `WEB_CONTENT`, etc.). |
| `source_identifier` | `str` | Domain-specific resource ID (e.g. `doc_pdf_101`, `postgres_table_users`). |
| `origin` | `str` | Description of pipeline component or retrieval system. |
| `parent_provenance_ids` | `List[str]` | List of parent provenance IDs (supports multi-parent derivation). |
| `timestamp` | `float` | UTC timestamp of record creation. |
| `content_hash` | `str` | Deterministic SHA-256 hex digest of the raw content string. |
| `metadata` | `Dict[str, Any]` | Extensible metadata payload. |

---

## 3. SHA-256 Content Fingerprinting

To detect out-of-band data tampering without storing redundant raw text in audit logs, AgentShield computes a SHA-256 fingerprint:

\[
\text{ContentHash} = \text{SHA256}(\text{RawContent})
\]

- **Integrity Verification**: `ProvenanceTracker.verify_integrity(provenance_id, current_content)` re-computes the SHA-256 hash of `current_content` and compares it with `record.content_hash`.
- **Content Hash invariant**: Hashing provides integrity fingerprints; it does **not** grant trust. A hash of untrusted web content remains `UNTRUSTED`.

---

## 4. Lineage Graph Architecture (`ProvenanceTracker`)

The `ProvenanceTracker` manages parent-child DAG (Directed Acyclic Graph) relationships across data transformations:

```
[ Root Doc A ] (provenance_id_1)         [ Root Doc B ] (provenance_id_2)
       │                                        │
       └───────────────────┬────────────────────┘
                           │
                           ▼ (Multi-Parent Derivation)
              [ Agent Summary C ] (provenance_id_3)
              parent_ids: [provenance_id_1, provenance_id_2]
```

### Key Operations

1. **`create_provenance(...)`**: Registers a root source record.
2. **`derive_from(parent_ids, ...)`**: Registers a derived record linking single or multiple parent provenance IDs.
3. **`get_ancestors(provenance_id)`**: Recursively traces all parent and ancestor records up to root sources.
4. **`verify_integrity(provenance_id, content)`**: Validates SHA-256 fingerprint against stored hash.

---

## 5. Derived Content & Trust Non-Elevation Rules

When content items \(A\) and \(B\) are combined into derived summary \(C\):

1. **Multi-Parent Reference**: \(C\) stores `parent_provenance_ids = [A.provenance_id, B.provenance_id]`.
2. **Lowest Trust Inheritance**: Derived content \(C\) does **not** gain `TRUSTED` status merely because it was generated by the agent. Its trust label inherits the lowest constituent trust level (`combine_trust_labels`).

---

## 6. Audit & Security Event Traceability

Security decisions and threat detection events log full provenance IDs:

```
Security Event (INJECTION_DETECTED)
       │
       ▼ (provenance_id)
ContextItem
       │
       ▼ (parent_provenance_ids)
Original Document Chunk ──► Root Knowledge Database
```

## 7. Current Implementation Status

### ✅ IMPLEMENTED
- `ProvenanceRecord` model with SHA-256 `content_hash` fingerprinting.
- `ProvenanceTracker` supporting `create_provenance`, `derive_from` (multi-parent derivation), `get_ancestors`, and `verify_integrity`.
- Fail-closed missing provenance handling (`INTERNAL_DATABASE` without `provenance_id` drops to `UNKNOWN` / `DENY`).
- Integration with `ContextItem` and `InstructionBoundary` preserving `provenance_id` and `content_hash`.
- Cryptographic hash-chained audit logging (`AuditLogger`).

### 🟡 PARTIALLY IMPLEMENTED
- Automatic database hook listeners for SQL/NoSQL storage (manual tracker registration required).

### ❌ NOT IMPLEMENTED
- Distributed cross-cluster lineage tracing over gRPC/OpenTelemetry protocols.

## 8. Usage Example

```python
from agentshield.provenance import ProvenanceTracker, compute_content_hash
from agentshield.context.models import SourceCategory

tracker = ProvenanceTracker()

# 1. Register root source
doc_rec = tracker.create_provenance(
    source_category=SourceCategory.VERIFIED_DOCUMENT,
    source_identifier="contract_2026.pdf",
    origin="sec_filings_db",
    content="Official agreement text..."
)

# 2. Derive RAG chunk
chunk_rec = tracker.derive_from(
    parent_ids=[doc_rec.provenance_id],
    source_category=SourceCategory.VERIFIED_DOCUMENT,
    source_identifier="chunk_1",
    origin="rag_chunker",
    content="Agreement snippet..."
)

# 3. Verify SHA-256 integrity
res = tracker.verify_integrity(chunk_rec.provenance_id, "Agreement snippet...")
print("Integrity Check Passed:", res["valid"])  # True
```
