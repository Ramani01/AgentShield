# Output & Action Security Validation Specification

## 1. Purpose & Core Security Invariant

The **Output & Action Validation Engine** (`OutputActionValidator`, `AgentOutput`, `AgentAction`) in AgentShield validates generated agent outputs and proposed actions **BEFORE** they leave the security boundary or are passed to any downstream execution layer.

The core security invariant for AgentShield Output & Action Validation is:
> **AGENT OUTPUT MUST NOT AUTOMATICALLY BE TREATED AS SAFE JUST BECAUSE IT WAS GENERATED BY THE AGENT.**

> [!IMPORTANT]
> Phase 11 validates outputs and proposed actions. **It does NOT execute external actions.**

---

## 2. Output Security Model

```python
class AgentOutput(BaseModel):
    output_id: str = Field(default_factory=lambda: str(uuid.uuid4()))
    content: str
    agent_id: str = "default_agent"
    user_id: str
    tenant_id: str
    provenance_id: Optional[str] = None
    content_hash: str = ""
    output_type: str = "text"
    metadata: Dict[str, Any] = Field(default_factory=dict)
    timestamp: float = Field(default_factory=time.time)
```

- **Classification**: Outputs are classified as `AGENT_GENERATED` data, **never** automatically `TRUSTED` data.

---

## 3. Action Security Model

```python
class AgentAction(BaseModel):
    action_id: str = Field(default_factory=lambda: str(uuid.uuid4()))
    agent_id: str = "default_agent"
    user_id: str
    tenant_id: str
    action_type: ActionType  # READ, WRITE, MEMORY_WRITE, DATA_EXPORT, API_REQUEST, TASK_EXECUTION
    target: str
    parameters: Dict[str, Any] = Field(default_factory=dict)
    provenance_id: Optional[str] = None
    timestamp: float = Field(default_factory=time.time)
```

---

## 4. Identity & Authorization Controls

- **Fail-Closed Identity Enforcement**: Outputs or actions lacking `user_id` or `tenant_id` are denied immediately (`SecurityDecision.DENY`).
- **Cross-Boundary Checks**:
  - `action.tenant_id == identity.tenant_id`
  - `action.user_id == identity.user_id` (unless `admin` role held)
- **Model Text vs Executable Action**: Agent text output proposing an action (e.g., `"Recommended action: MEMORY_WRITE"`) does **NOT** grant authorization or execute the action. Action validation is required.

---

## 5. Security Invariants (20 Invariants Enforced)

- **INVARIANT 1**: Agent-generated output is not automatically trusted.
- **INVARIANT 2**: Agent-generated actions are not automatically authorized.
- **INVARIANT 3**: Output cannot modify its own authorization metadata.
- **INVARIANT 4**: Output cannot modify its own trust level.
- **INVARIANT 5**: Output cannot modify its own tenant identity.
- **INVARIANT 6**: Output cannot modify its own user identity.
- **INVARIANT 7**: Valid provenance does not automatically make output trusted.
- **INVARIANT 8**: Valid hash does not automatically make output trusted.
- **INVARIANT 9**: Sensitive output must not be released when policy denies secrets.
- **INVARIANT 10**: Unauthorized actions must be denied.
- **INVARIANT 11**: Cross-user actions must be denied.
- **INVARIANT 12**: Cross-tenant actions must be denied.
- **INVARIANT 13**: Missing security identity fails closed.
- **INVARIANT 14**: Missing required action target fails closed.
- **INVARIANT 15**: Invalid action parameters fail closed.
- **INVARIANT 16**: High-risk actions support `SecurityDecision.REVIEW`.
- **INVARIANT 17**: Proposed actions must not execute automatically.
- **INVARIANT 18**: Output validation occurs before external release.
- **INVARIANT 19**: Action validation occurs before any future executor would receive approval.
- **INVARIANT 20**: Rejected output/action decisions are recorded in audit logs.

## 7. High-Risk Action Review & Secret Detection

- **High-Risk Actions**: `DATA_EXPORT`, `MEMORY_WRITE`, `TASK_EXECUTION`, or actions targeting export/security scopes yield `is_high_risk = True` and `SecurityDecision.REVIEW`.
- **Secret Detection**: `SecretDetector` scans outputs for unredacted credentials. Detected secrets set `sensitive_data_detected = True` and `SecurityDecision.DENY` without logging raw secret text.

---

## 8. Auditability

Structured audit logs record:
- `OUTPUT_VALIDATED` / `OUTPUT_BLOCKED`
- `ACTION_APPROVED` / `ACTION_REVIEW` / `ACTION_BLOCKED`

Raw secrets, credentials, and sensitive parameter values are **never** logged.

---

## 9. Limitations & Disclaimer

> [!WARNING]
> **Explicit Security Disclaimer**:
> Output and action validation establishes strict security inspection boundaries before output release or action approval. It does not execute external actions or guarantee downstream LLM reasoning correctness.
