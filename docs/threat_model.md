# AgentShield Formal Threat Model

This document establishes the formal threat model for the **AgentShield** framework. It details system assets, trust boundaries, trust levels, threat categories, security decision models, security principles, and the formal threat matrix.

---

## 1. Assets Analysis

AgentShield identifies and protects eight critical asset classes within autonomous AI agent ecosystems:

| Asset ID | Asset Name | Description & Sensitivity |
|---|---|---|
| **A-01** | **System/Developer Instructions** | System prompts, developer instructions, system persona definitions, and core governance rules. Highest confidentiality and integrity requirements. |
| **A-02** | **User Instructions** | Explicit queries, tasks, and commands provided by the user requesting agent execution. |
| **A-03** | **Retrieved Context** | External documents, vector database search results, web scrapings, and knowledge base extracts retrieved during RAG operations. |
| **A-04** | **External / Untrusted Content** | Raw payload data from web pages, emails, APIs, third-party services, and untrusted files. |
| **A-05** | **Agent Memory** | Short-term conversation history, long-term vector embeddings, persistent state stores, and entity graphs across sessions. |
| **A-06** | **Provenance Metadata** | Execution lineage graphs, audit logs, cryptographic SHA-256 hash chains, trace IDs, and security telemetry. |
| **A-07** | **Agent Decisions / Actions** | Tool invocation choices, function arguments, plan generation, and sub-agent delegation directives. |
| **A-08** | **Outgoing Data** | Agent responses, generated files, external API request payloads, and user-facing outputs. |

## 2. Trust Boundaries

Trust boundaries delineate zones where data transitions between differing trust levels or privilege contexts:

```
[ TRUSTED / SYSTEM ] 
       │
   (Boundary 1: Instruction Boundary)
       ▼
[ USER_CONTROLLED ] ──(Boundary 2: Context Boundary)──► [ AGENT EXECUTION PIPELINE ]
                                                                 │
                                                       (Boundary 3: Retrieval Boundary)
                                                                 ▼
                                                       [ UNTRUSTED RAG / WEB ]
                                                                 │
                                                       (Boundary 4: Memory Boundary)
                                                                 ▼
                                                       [ AGENT MEMORY STORE ]
                                                                 │
                                                       (Boundary 5: Action / Output Boundary)
                                                                 ▼
                                                       [ TOOL / FUNCTION EXECUTION ]
                                                                 │
                                                       (Boundary 6: Egress Boundary)
                                                                 ▼
                                                       [ EXTERNAL NETWORK / USER ]
```

1. **Instruction Boundary (TB-01)**: Separates developer system prompt authority from user-supplied prompt text.
2. **Context Boundary (TB-02)**: Separates prompt context components (System vs. User vs. Tool Output) to prevent token delimiter spoofing.
3. **Retrieval Boundary (TB-03)**: Separates internal agent processing from untrusted external retrieval sources (vector stores, web search).
4. **Memory Boundary (TB-04)**: Separates active runtime execution memory from long-term persistent or multi-tenant memory stores.
5. **Action/Output Boundary (TB-05)**: Separates LLM text generation from tool execution and system command dispatchers.
6. **Egress Boundary (TB-06)**: Separates internal agent environment from external networks, user interfaces, and remote storage.

---

## 3. Trust Levels Classification

AgentShield categorizes all data inputs, state objects, and execution components into five formal trust levels:

- **`TRUSTED`**: Code, configuration files, system prompts, and policies defined by the system administrator/developer.
- **`INTERNAL`**: Transient execution state, cryptographic hash chains, telemetry metrics, and internal trace metadata generated by AgentShield.
- **`USER_CONTROLLED`**: Prompts, parameters, and commands provided directly by authenticated users.
- **`UNTRUSTED`**: Content retrieved from external search engines, web scraping, third-party APIs, untrusted files, or public databases.
- **`UNKNOWN`**: Inputs or objects with unverified origin, unvalidated schema, or missing cryptographic signatures.

## 4. Threat Categories

AgentShield defines 12 core threat categories targeting AI agent architectures:

1. **Instruction Manipulation (T-01)**: Overriding system instructions or altering agent developer personas through direct phrasing.
2. **Prompt Injection (T-02)**: Direct or indirect injection of commands within user text or external data to compromise agent control flow.
3. **Untrusted Retrieved Content (T-03)**: Ingestion of malicious payloads or hidden directives from RAG knowledge bases or scraped websites.
4. **RAG Authorization Failure (T-04)**: Unauthorized retrieval of restricted knowledge base documents exceeding user privilege level.
5. **Memory Poisoning (T-05)**: Injecting malicious directives or false facts into persistent agent memory to affect future sessions.
6. **Unauthorized Memory Modification (T-06)**: Out-of-band tampering or cross-tenant contamination of stored agent state.
7. **Context Integrity Violation (T-07)**: Delimiter collision or token boundary escaping causing the LLM to treat untrusted data as system instructions.
8. **Unsafe Agent Decision (T-08)**: Generation of dangerous tool calls (e.g. command execution, file deletion, database modification).
9. **Unauthorized Data Egress (T-09)**: Accidental or malicious exfiltration of PII, secrets, or API keys in outgoing outputs.
10. **Token Audience Confusion (T-10)**: Misinterpreting unprivileged user inputs as authoritative system directives due to role ambiguity.
11. **Tool-Definition Tampering (T-11)**: Manipulation of tool parameter schemas, descriptions, or function bindings.
12. **Unsafe State Recovery (T-12)**: Restoring agent state from corrupted, altered, or unverified checkpoint stores.

## 5. Security Decisions

When evaluating an operation, input, or tool call, AgentShield enforces one of four formal security decisions:

- **`ALLOW`**: The operation passed all security scans, policy constraints, and privilege checks. Proceed with execution.
- **`DENY`**: The operation violated a security policy or contained a critical threat. Block execution immediately and raise an exception.
- **`ISOLATE`**: The data contains potential risks or untrusted elements. Strip, sanitize, escape, or quarantine before processing.
- **`REVIEW`**: The operation exceeds risk thresholds or requires explicit human-in-the-loop (HITL) approval prior to execution.

---

## 6. Core Security Principles

AgentShield operates under eight architectural security principles:

1. **Least Privilege**: Agents and tools execute with the minimum required access rights and role permissions.
2. **Explicit Trust Boundaries**: Strict separation and tag-wrapping between System instructions, User inputs, and Tool outputs.
3. **Fail Closed**: Any security ambiguity, parsing error, or policy check failure results in an immediate `DENY` decision.
4. **Provenance Preservation**: All actions, decisions, and data flows are cryptographically logged in an append-only audit log.
5. **Separation of Data and Instructions**: Untrusted inputs are strictly treated as data and never parsed as executable system instructions.
6. **Policy-Driven Decisions**: Security enforcement is governed by externalized, declarative policy rules rather than hardcoded logic.
7. **Auditability**: Complete end-to-end trace lineage (User -> Agent -> Tool -> Output) with SHA-256 hash validation.
8. **Safe Recovery**: Memory and state restoration require signature verification before activation.

## 7. Threat Matrix

| Threat ID | Threat Category | Asset Affected | Trust Boundary Crossed | Potential Impact | Intended AgentShield Control | Default Decision |
|---|---|---|---|---|---|---|
| **TM-01** | Prompt Injection | A-01, A-07 | TB-01 (Instruction) | Total agent takeover, system prompt bypass | `PromptInjectionScanner` pattern analysis & score thresholding | `DENY` |
| **TM-02** | Jailbreak Attack | A-01, A-07 | TB-01 (Instruction) | Safety filter bypass, dangerous response generation | `JailbreakDetector` heuristic vector matching | `DENY` |
| **TM-03** | Delimiter Spoofing | A-01, A-02 | TB-02 (Context) | Context pollution, instruction confusion | `ContextBoundary` token escaping & system wrapping | `ISOLATE` |
| **TM-04** | Privilege Escalation | A-01, A-07 | TB-01 (Instruction) | Unauthorized administrative action execution | `PrivilegeIsolator` role hierarchy validation | `DENY` |
| **TM-05** | Token Exhaustion | A-02, A-07 | TB-02 (Context) | Denial of service, budget overrun, context overflow | `TokenManager` budget enforcement & sliding window truncation | `ISOLATE` |
| **TM-06** | RAG Document Poisoning | A-03, A-07 | TB-03 (Retrieval) | Indirect prompt injection via retrieved vector docs | `PoisonDocumentFilter` scanning before context insertion | `ISOLATE` |
| **TM-07** | RAG Unauthorized Access | A-03 | TB-03 (Retrieval) | Information disclosure of restricted knowledge base docs | `DocumentAccessControl` role-based document ACL filtering | `DENY` |
| **TM-08** | Memory Injection | A-05 | TB-04 (Memory) | Persistence of malicious payloads across agent sessions | `MemoryFilter` PII & secret sanitization before write | `ISOLATE` |
| **TM-09** | Memory Tampering | A-05 | TB-04 (Memory) | Unintended state mutation, cross-tenant leak | `SafeMemoryStore` tenant isolation & `TamperDetector` HMAC/SHA-256 signatures | `DENY` |
| **TM-10** | Unsafe Tool Call | A-07 | TB-05 (Action) | OS command injection (`rm -rf`), SQL drop, path traversal | `VulnerabilityScanner` regex inspection & `@shield_tool` interceptor | `DENY` |
| **TM-11** | Policy Violation | A-07 | TB-05 (Action) | Execution of unapproved or constrained tools | `PolicyEngine` evaluation against YAML policy rules | `DENY` |
| **TM-12** | Secret Leakage | A-08 | TB-06 (Egress) | Exfiltration of AWS keys, OpenAI tokens, JWTs, SSH keys | `SecretDetector` regex scanning & automatic redaction | `ISOLATE` |
| **TM-13** | PII Exfiltration | A-08 | TB-06 (Egress) | Privacy compliance breach (GDPR / HIPAA) | `InputOutputSanitizer` regex PII masking | `ISOLATE` |
| **TM-14** | Audit Log Tampering | A-06 | TB-06 (Egress) | Loss of auditability, security event concealment | `AuditLogger` SHA-256 hash chaining & log verification | `DENY` |

## 8. Current Implementation Status

Based on strict inspection of the existing codebase (`agentshield/`):

### ✅ Implemented
- **Prompt Injection & Jailbreak Scanning**: Basic regex pattern matching (`PromptInjectionScanner`, `JailbreakDetector`) with thresholding score calculation.
- **PII & Secret Sanitization**: Standard regex patterns for AWS keys, OpenAI keys, JWTs, emails, SSNs, credit cards, phones (`InputOutputSanitizer`, `SecretDetector`).
- **Basic Context Boundary Escaping**: Delimiter tag escaping (`ContextBoundary`) and simple token estimation truncation (`TokenManager`).
- **In-Memory Safe Store & Tamper Signature**: Tenant key hash isolation (`SafeMemoryStore`) and HMAC/SHA-256 verification (`TamperDetector`).
- **Basic RAG Filtering**: Document ACL role check (`DocumentAccessControl`) and injection scan on retrieved text (`PoisonDocumentFilter`).
- **Basic Policy Engine**: Loading YAML policy rules (`PolicyEngine`, `PolicyParser`) for tool whitelist/blacklist and forbidden path string matching.
- **Cryptographic Audit Logger**: JSONL append-only logger with SHA-256 hash chaining (`AuditLogger`) and integrity checker.
- **Basic Lineage & Telemetry**: Graph node recorder (`ActionLineage`) and runtime event counter (`ExecutionTelemetry`).

### 🟡 Partially Implemented
- **Vulnerability Scanning**: Regex checking for specific static strings (`rm -rf`, `drop table`, `../`), but lacks AST analysis or dynamic shell parser.
- **Privilege Isolation**: Simple role hierarchy integer check (`PrivilegeIsolator`) and hardcoded string check, lacking granular policy permission mapping.

### 🟠 Scaffolded But Not Verified
- **FastAPI Server & Client SDK**: Endpoints created in `agentshield/api/fastapi_app.py` and `sdk.py`, but microservice authentication, rate-limiting, and error middleware are basic stubs.
- **WSGI/ASGI Middleware**: `AgentShieldMiddleware` in `middleware.py` is a pass-through wrapper stub.

### ❌ Not Implemented
- **AST / Semantic Tool Argument Parser**: Deep syntactic evaluation of shell commands or SQL queries.
- **Vector Store Database Integration**: Direct bindings to ChromaDB, Pinecone, Qdrant, or FAISS.
- **Human-in-the-loop (HITL) Workflow**: Interactive `REVIEW` decision flow and approval queues.
- **Dynamic Policy Reloading**: Real-time hot-reloading of policy definitions without restarting the agent process.
